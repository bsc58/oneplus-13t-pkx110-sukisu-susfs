# 06 · 长期注意事项

## 一、硬件防回滚(最重要)

社区反馈称,13T 从 **ColorOS 16.0.3.501** 起(以及某些降级包)启用了**硬件防回滚**。一旦升级到该版本及以上,**再刷旧版固件会直接变砖**,无法降级。

- **不要升级到 ColorOS 16.0.3.501 及以上。**
- 升上去之后,本仓库里针对旧固件构建的任何镜像都**不要再刷**。

## 二、OTA(系统在线升级)

OTA 会**覆盖 `boot` 分区**,结果就是:**掉 root、你自编的内核没了**,而且升级后你为旧版固件准备的镜像**不再匹配**。更糟的是可能在不知不觉中升到带防回滚的新版本(有 13T 用户在 root 状态下夜里被自动升级)。

**对策:**

1. **关闭系统自动更新 / 夜间更新。**
2. 真要升级时:**先按 [`05-recovery.md`](05-recovery.md) 刷回原厂 `boot` + `init_boot`**,再走官方 OTA;升级完这些旧镜像作废,需要为新版本重新构建。
3. 想更彻底地禁掉 OTA:可用 root 禁用/卸载 OPLUS 的 OTA 相关系统应用(按你的系统为准,常见包名有 `com.oplus.ota`、`com.oplus.romupdate`、`com.coloros.ota`、以及升级引导/下载类组件)。
   - 卸不掉的(受保护)用 `pm disable-user --user 0 <包名>` 禁用,等效。
   - `update_engine` 这类系统守护进程在只读系统分区里删不掉,但**没有 OTA 应用去触发它,它就处于休眠**,不会自己升级。
   - 保留谷歌的配置更新(`com.google.android.configupdater`,非固件)、应用商店的 app 更新等——它们**只更 app,不碰系统固件**,不会掉 root 或变砖。

> 注意区分:**固件 OTA**(会覆盖内核、危险)vs **应用更新**(商店更 app,无害)。只需要掐死前者。

## 三、模块更新

一个**已经全绿、稳定**的隐藏环境,不要为了追新去更新模块。

- 更新模块**最坏是某模块抽风**(黑屏/不生效),**禁用或回退上一版即可,不会砖**。
- 真要更新:**一次只更一个**,更完**重启并跑一遍 Ruru + 常用 app** 确认没回退,再动下一个。
- 作为 **Zygisk 提供者 / Xposed 框架**的那几个(Zygisk Next、LSPosed)是其它模块的地基,牵一发动全身,更新尤其谨慎。
- 换过内核后,原有模块是否都正常**只能实测**(它们不会丢,见 [`03-flash-and-boot.md`](03-flash-and-boot.md));逐个开、逐个验。

## 四、换内核 / 刷机后的习惯

- 每次系统有任何「软件更新」提示,先想清楚它会不会覆盖 boot。
- 重大改动前,保持 [`05-recovery.md`](05-recovery.md) 里的原厂镜像备份是最新且可用的。
- 记住你的**固件版本**和**构建时钉的 `KERNEL_REF`**;以后重建或排查都要用。
